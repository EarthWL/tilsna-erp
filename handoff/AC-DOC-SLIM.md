### 1.2 ผมเอาหลักฐานของทางนั้นไปใช้ และมันขัดกับตัวสกิลเอง

จาก commit `5aa28f0` ของทางนั้น — `hap workflow list` ให้ผล **50/37/36 จาก 3 ครั้งติด** และ `workflow structure` คืนค่าแม้ถูกลบแล้ว

เรื่องนี้สำคัญกว่าที่คิด เพราะ **สกิล v2.8.2 เขียนว่า `hap workflow list <appId>` "returns every workflow" และติดป้าย [V] ยืนยันแล้ว** — ซึ่งแรงเกินจริงตามหลักฐานของทางนั้น
ผมจึงไม่ได้เขียนเอกสารฝั่ง accounting ว่า "เปลี่ยนจาก Browser ไปใช้ `hap workflow list`" ตรง ๆ แต่เขียนเป็น **คำตอบ 3 ชั้น** ทุกจุด:

| ต้องการรู้อะไร | ใช้อะไร | ห้ามใช้ |
|---|---|---|
| สำรวจว่ามี workflow อะไรบ้าง | `hap workflow list <appId>` | — |
| **ยืนยันว่า "ไม่มี"** | ❌ ไม่มีเครื่องมือไหนพิสูจน์ได้ | `get_workflow_list` (เห็นแค่ PBP) · `hap workflow list` (ผลไม่คงที่) |
| ยืนยันว่าตัวนี้ยังอยู่จริงไหม | **`hap workflow get <id>` → ดูฟิลด์ `deleted`** | `workflow structure` (คืนค่าแม้ลบแล้ว) |

### 1.3 🆕 กับดัก "Unassigned View" ที่ทางนั้นเพิ่งเขียนเป็นไกด์ §2 ข้อ 21 — **ตรวจผ่าน CLI ได้ ไม่ต้องเปิด Browser**

**ทางนั้นน่าจะรันคำสั่งนี้กับ worksheet ฝั่ง hr ดูด้วย** — ผมเจอว่าฝั่ง accounting มีปุ่ม 2 ปุ่มที่ workflow ทดสอบผ่านครบแล้วแต่ผู้ใช้กดไม่ได้เลยเพราะ Scope ค้าง

**ถ้าเห็นว่าผมสรุปหลักฐานของทางนั้นผิด บอกได้เลย ผมแก้ให้** — และน่าจะคุ้มที่จะส่งเรื่องนี้กลับไปแก้ที่ตัวสกิลด้วย เพราะป้าย [V] ตรงนั้นแรงเกินหลักฐาน

### ขั้นตอนที่ทำ (เสนอให้ทำเหมือนกัน)

**① เช็คความปลอดภัยก่อนตัด — นี่คือขั้นที่ห้ามข้าม**
ก่อนลบอะไร ผมดึง **ID ทุกตัว** (24-hex + uuid) ออกจากข้อความที่จะตัด แล้วเช็คว่าแต่ละตัวมีอยู่ที่อื่นในเอกสารชุดเดียวกันไหม

```python
ids = set(re.findall(r'\b[0-9a-f]{24}\b', chunk_to_delete))
# แล้วเทียบกับเนื้อหาไฟล์อื่น + ส่วนที่เหลือของไฟล์เดียวกัน
```

ผลฝั่ง accounting: **ID ทั้ง 18 ตัวในบรรทัดที่ยุบ มีอยู่ที่อื่นครบทุกตัว ⇒ ตัดได้ไม่มีอะไรหาย**
ส่วนตอนยุบ section "สถานะงานล่าสุด" เจอ **1 ID ที่มีอยู่ที่นั่นที่เดียว** (`6a861cfef520ee95fb0c3a3a` — stale draft ของ WF-AC-02 ที่ถูกลบตอน audit) จึง**ยกมันขึ้นมาเก็บไว้ในข้อความ pointer แทนที่จะปล่อยหาย**

**② ยุบบรรทัดประวัติ — เก็บรอบล่าสุดรอบเดียว**
ตัดที่ `(รอบก่อนหน้า:` ตัวแรก ทิ้งทุกอย่างหลังจากนั้น แล้วต่อท้ายด้วยข้อความที่ระบุ 4 อย่าง: ยุบเมื่อไร · ตัดไปกี่ชั้น/กี่ตัวอักษร · **ยืนยันว่าเช็ค ID แล้วไม่มีอะไรหาย** · คำสั่ง git ที่อ่านย้อนได้ + **กฎห้ามซ้อนอีก**

**③ section "สถานะงานล่าสุด" → เหลือ pointer**
ของเดิมเป็นสำเนา Roadmap ที่ต้อง sync ด้วยมือ = แหล่ง drift โดยตรง

> 🔴 **แก้ตัวเลข + บทเรียนที่อยากเตือนก่อนทางนั้นจะวัดไฟล์ตัวเอง**
> ผมรายงานรอบแรกผิดเป็น "−43% / −34%" เพราะ **วัด "ก่อน" ด้วย `wc -w` บนเครื่อง device (locale UTF-8) แต่วัด "หลัง" ด้วย `wc -w` ใน cloud sandbox (locale C)** — `wc -w` ใน locale C แยกไบต์ UTF-8 ไทยผิด ให้ตัวเลขต่ำกว่าจริงราว 34% ⇒ เทียบข้ามเครื่องแล้วได้ตัวเลขสวยเกินจริง
> **ห้ามใช้ `wc -w` กับข้อความไทยเว้นแต่ตั้ง `LC_ALL=C.UTF-8` และห้ามเทียบตัวเลขที่วัดคนละเครื่องกัน** — นับด้วย Python (`len(t.encode('utf-8'))` / `len(t)`) หรือใช้ **bytes** เป็นหน่วยหลักแบบที่ทางนั้นทำอยู่แล้ว ซึ่งถูกต้องกว่าเพราะ locale ไม่มีผล
> (ตัวเลข "คำ" ในตาราง §C ที่วัดไว้ 28 ส.ค. ก็ควรถือว่ายังไม่ได้ตรวจสอบวิธีวัดเช่นกัน)
