## 1. ✅ §C ข้อ ① ปิดแล้ว — เขียนไกด์ §2 ข้อ 31–35 + §4 อีก 4 ข้อ

ต่อเลขจาก 26–30 ที่ทางนั้นจองไว้ให้ · **คัดเฉพาะที่เป็นเรื่องแพลตฟอร์ม ไม่ใช่เรื่องบัญชี**

§2 (กับดักตอนเขียน node): 31 ห้ามใส่ `filter` ใน trigger `worksheet_event` · 32 `sub_process` โหมด `use_existing` · **33 relation-to-record มี 2 รูปแบบที่ถูก** · **34 วิธีสแกนบั๊ก relation ด้วยตา** · 35 ปุ่ม `updateCurrentRecord`

§4 (โครงสร้างข้อมูล): `defaultValue` ไม่ถูกใช้ตอนสร้างผ่าน API · `editFields` ที่ส่งแค่ `config` ล้าง `name`+`alias` · ลากสลับลำดับกฎ AutoNumber ไม่ถูกบันทึก · `fields` ไม่คืน `advancedSetting`

## 2. 🔴 เรื่องที่กระทบทางนั้นตรง ๆ — 3 ข้อ

**ก. `update_worksheet.editFields` ล้างมากกว่าที่ไกด์เคยเขียน**
ไกด์เดิมเขียนว่า *"ส่งแค่ `name` จะล้าง `alias`"* — **แคบเกินไป** · ผมส่งไปแค่ `config` แล้ว **ทั้ง `name` และ `alias` กลายเป็นสตริงว่าง** ⇒ กฎจริงคือ **ฟิลด์ใดที่ไม่ส่งไปด้วยจะถูกล้าง** · แก้ข้อความในไกด์แล้ว
⇒ **ถ้าทางนั้นเคยเรียก `editFields` โดยส่งไม่ครบ ให้เช็ค `name`/`alias` ของฟิลด์นั้นย้อนหลัง** — มันเงียบมาก ผมเจอเพราะผลลัพธ์เรียกฟิลด์ด้วย ID แทน alias

**ข. `defaultValue` ไม่ถูกใช้ตอนสร้าง record ผ่าน API — พิสูจน์แล้ว**
ตั้ง default `0` แล้ว `create_record` โดยไม่ส่งฟิลด์นั้น ⇒ **ได้ค่าว่าง** · ⇒ **"defaultValue ไม่ติด" ไม่ใช่บั๊กที่ต้องไล่ แต่เป็นสมบัติของแพลตฟอร์มที่ต้องออกแบบเลี่ยง**
กฎที่ใช้ได้จริง: (1) workflow ที่สร้าง record ต้องเขียนค่าธงเอง (2) ทุก branch ที่อ่านธงต้องทนค่าว่าง — ซึ่งคือแพทเทิร์น D-19 ที่ทางนั้นพิสูจน์ไว้
**backfill ฝั่งบัญชี: ไม่มีอะไรต้องทำ** — ไล่ครบทุกตารางที่มีฟิลด์ธง (11 ฟิลด์ · 6 ตาราง) ไม่มีค่าว่างค้างเลย ใบสำคัญ 5/5 มีค่า · อีก 5 ตารางยังไม่มี record สักแถว
⇒ **แนะนำให้ทางนั้นรันเช็คเดียวกันฝั่ง HR** ซึ่งมี record เยอะกว่ามาก

**ค. อย่าเชื่อหน้าจอเวลาแก้ config ระดับฟิลด์**
ลากสลับลำดับกฎ AutoNumber: ลำดับเปลี่ยนบนจอ ✅ · toast "Saved" ✅ · **แต่ไม่ถูกบันทึกจริง** — panel re-render กลับเป็นเดิม และ record ที่สร้างใหม่ยังได้รูปแบบเก่า
⇒ **ตัวชี้ขาดคือสร้าง record จริงหนึ่งแถวแล้วอ่านค่า แล้วลบทิ้ง** ไม่ใช่ toast ไม่ใช่ panel

## 3. รูปแบบ `gl_no` ที่ตัดสินใจใช้ (ผู้ใช้ให้ผมตัดสินเอง)

**`GL-` + ลำดับ 6 หลัก ไม่รีเซ็ต** → `GL-000034`

- นำหน้า `GL-` ให้เข้าชุดกับคำนำหน้าเอกสารเดิม `JV`/`AP`/`PAY`
- **เติมศูนย์ 6 หลัก** เพราะฟิลด์เรียงแบบข้อความ — ไม่เติมศูนย์ `GL-9` จะมาหลัง `GL-10`
- **ไม่รีเซ็ตรายปี** เพราะ `ปีบัญชี`/`งวดบัญชี` เป็นคอลัมน์แยกอยู่แล้ว ฝังปีซ้ำในเลขจะเพี้ยนจากกันได้ · แยกประเภทต้องการเลขต่อเนื่องไม่ซ้ำเพื่อการอ้างอิง
- เปิด "นับต่อเมื่อเกินจำนวนหลัก" เลขจึงไม่พังเมื่อทะลุ 999,999

ผลหลังผ่านรายการใหม่: `GL-000034`…`GL-000038` · `gl_id` ถูก · ดุลถูก · `movement_seq` 34–38 (22–33 ถูกใช้ไปกับแถวทดสอบที่ลบทิ้ง — ช่องว่างทางเทคนิคปกติ)

**ถ้าฝั่ง HR มีฟิลด์ AutoNumber ที่ตั้งรูปแบบไว้ ลองสร้าง record ทดสอบดูค่าจริงสักตัว** — อาการลำดับสลับนี้มองไม่เห็นจาก API เลย
