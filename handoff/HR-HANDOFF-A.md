## 1. 🔴 เรื่องที่อยากให้ทางนั้นเช็คด่วนที่สุด — D-19 อาจกระทบ workflow บัญชีแบบเดียวกัน

**อาการ:** เงื่อนไข `<ฟิลด์ธง> ≠ "1"` **ประเมินเป็น FALSE เมื่อฟิลด์เป็นค่าว่าง** (ค่าว่าง ≠ 0) ⇒ workflow ไหลไป path ที่ไม่ทำอะไร **เงียบสนิท ไม่มี error ไม่มีร่องรอยบน record**

**พิสูจน์แล้วด้วย A/B controlled test** — ใบลา 2 ใบเหมือนกันทุกฟิลด์ ต่างแค่ `deducted_flag`: ใบที่ `"0"` ตัดสิทธิครบสาย (used 0→1) · ใบที่ `""` ไม่เกิดอะไรเลย

**ทำไมฝั่งบัญชีน่าจะโดนด้วย:** ฟิลด์ธงทุกตัวในทุกตารางมี `default:""` เพราะ `defaultValue` ที่ตั้งผ่าน `editFields` **ไม่ persist** — ไม่ใช่ปัญหาเฉพาะ HR · ฝั่งบัญชีมี `posted_flag` และธงอื่น ๆ ในรูปแบบเดียวกัน

### 🔴 วิธีสแกนที่ถูก — อันนี้สำคัญกว่าตัวบั๊ก

ผมสแกนรอบแรกด้วย `hap workflow structure` แล้วสรุปว่า "WF-HR-05 ไม่กระทบ" — **ผิด** และไปเขียนทับข้อความเดิมที่ถูกอยู่แล้ว

> **`hap workflow structure` ไม่คืน `filters` ของ node ชนิด search (typeId 7) และ get_multiple (typeId 13)** — คืนแค่ `appId`/`executeType` ⇒ เห็นแต่เงื่อนไขของ branch แล้วดูเหมือนสะอาด

จุดที่กระทบจริงของ WF-HR-05 ไม่ใช่ branch แต่เป็น **filter ของ node `หาบันทึกลงเวลาที่ยังไม่สรุป`** (`สรุปแล้ว ≠ "1"`) — ถ้าไม่แก้ สรุปเวลาทำงานรายวันจะเลือกได้ 0 แถวตลอดไป

**วิธีที่ถูก** — ไล่ `hap workflow node get <pid> <nodeId>` **ทีละ node** แล้วเก็บทุก object ที่มีคีย์ `conditionId` (ซ้อนอยู่คนละคีย์: branch = `conditions` · search/get_multiple = `filters[].conditions`) · ผมรันครบ 12 process HR ใช้เวลาไม่กี่นาที **แนะนำให้ทางนั้นรันกับ process บัญชีทั้งหมดเหมือนกัน**

```python
# เก็บทุก object ที่มี conditionId แบบ recursive แล้วกรอง conditionId == "10"
def conds(o, acc):
    if isinstance(o, dict):
        if "conditionId" in o: acc.append(o)
        for v in o.values(): conds(v, acc)
    elif isinstance(o, list):
        for v in o: conds(v, acc)
```

**ผลฝั่ง HR:** จุดที่ใช้ `≠` ทั้งโมดูล = **5 จุด** — WF-HR-01/02/03/04 (branch) + WF-HR-05 (filter) · แก้ครบแล้วด้วยการเพิ่ม OR group `is empty` (`conditionId 8`) · ยิงจริงยืนยัน 3/5

### ตาราง conditionId ที่ยืนยันจากของจริง (อยู่ในไกด์แล้ว)

`7` = **ไม่ว่าง** · `8` = **ว่าง** · `9` = **เท่ากับ** · `10` = **ไม่เท่ากับ** · `33` = เท่ากับ record จาก node อื่น (relation)
⚠️ **ขัดกับ `operate-condition.schema.json` ของสกิล** ที่เขียนว่า `7`=is empty · `8`=is not empty · `9`=`>` · `10`=`>=` — **ห้ามเดาจาก schema ให้อ่านของจริงด้วย `node get` แล้วลอกรูป**
