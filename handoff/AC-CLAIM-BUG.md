## เจอได้ยังไง

`preflight` ของผมเช้านี้ขึ้น `PREFLIGHT WARN: ปลด CLAIM ค้างของ agent-ac ... เกิน 8h` **สองใบ ทั้งที่ผม `--release` ไปเรียบร้อยแล้วทั้งคู่** และ log ก็มีบรรทัด `RELEASE` อยู่จริง ⇒ ตัวอ่านมองไม่เห็นการปล่อย

## สาเหตุ — ช่องว่างซ้อนหนึ่งตัว ทำให้ฟิลด์เลื่อนทั้งบรรทัด

`preflight.sh` เขียนใบจองด้วย

```sh
echo "CLAIM $(now_iso) $APP $TASK $OBJS" >> "$LOG"
```

ถ้าเรียก preflight โดยส่ง `""` เป็น appId (ซึ่งผมทำมาหลายครั้ง) จะได้ **ช่องว่างซ้อน** แล้ว `awk` ยุบช่องว่าง ⇒

| | ตั้งใจให้เป็น | ที่ awk อ่านได้จริง |
|---|---|---|
| `$3` | appId | **task** |
| `$4` | task | **objects** |
| `$5` | objects | *(ว่าง)* |

`active_claims` คีย์ CLAIM ด้วย `c[$4]` แต่คีย์การปิดด้วย `closed[$3]` ⇒ **คีย์คนละอย่าง ไม่มีวัน match**

## ผลกระทบจริง 2 ข้อ — ข้อที่สองอันตราย

1. ใบจองที่ปล่อยแล้วยังนับเป็น active จนหมดอายุ TTL 8 ชั่วโมง (แค่รก)
2. 🔴 **`objs` ที่อ่านกลับได้เป็นสตริงว่าง** และ `app` กลายเป็นชื่อ task ⇒ ใน `preflight.sh`
   - บรรทัด `[ "$app" != "$APP" ] && continue` **ข้ามใบจองนั้นทิ้งทันที**
   - ต่อให้ไม่ข้าม `objects_overlap "" "..."` ก็ไม่มีวันชน
   ⇒ **ใบจองนั้นมองไม่เห็นจากฝั่งตรงข้าม — อีกฝั่งเดินทับได้โดยไม่มีคำเตือนใด ๆ**

**แปลว่าตอนผมแก้บั๊ก Relation ของ WF-AC-02 เมื่อคืน (claim `AC/WF02-RELATION-FIX`) ผมถือใบจองที่มองไม่เห็น** — ถ้าทางนั้น preflight ทับ `projects/accounting/*` ตอนนั้น จะได้ OK ทั้งที่ควรถูกบล็อก · โชคดีที่ไม่เกิด แต่เป็นเรื่องของโชค ไม่ใช่ของ guardrail

## พิสูจน์ — ป้อน log ชุดเดียวกันให้ตัวอ่านเก่ากับใหม่

```
CLAIM   ... appA X/ONE   projects/a/*,handoff/X-*      ← appId ครบ
RELEASE ...      X/ONE
CLAIM   ...      X/TWO   projects/b/*,handoff/X-*      ← appId ว่าง (ช่องว่างซ้อน)
RELEASE ...      X/TWO
CLAIM   ...      X/THREE projects/c/*                  ← appId ว่าง · ยังไม่ปล่อย
```

**ตัวอ่านเดิม** — X/TWO โผล่มาเป็น active ทั้งที่ปล่อยแล้ว และ **ช่อง objects ว่างทั้งสองแถว**:
```
agent-x|...02:00:00Z|X/TWO  |projects/b/*,handoff/X-*|
agent-x|...03:00:00Z|X/THREE|projects/c/*            |
```

**ตัวอ่านใหม่** — เหลือใบเดียวที่ยังถืออยู่จริง และ objects ครบ:
```
agent-x|...03:00:00Z|-|X/THREE|projects/c/*
```

## แก้อย่างไร (แก้แล้ว commit แล้ว)

1. `preflight.sh` — `APP="${3:--}"` บังคับให้มีค่าเสมอ ใช้ `-` แทนเมื่อไม่ระบุ ⇒ บรรทัดใหม่จะไม่เลื่อนอีก
2. `preflight.sh` — เงื่อนไขข้ามแอปเปลี่ยนเป็น *"ข้ามเฉพาะเมื่อทั้งสองฝั่งระบุแอปจริงและไม่ตรงกัน"* ⇒ ใบจองที่ไม่ระบุแอปจะถูกนำมาเทียบด้วย ไม่ถูกข้าม
3. `claimlib.sh` — `active_claims` อ่านตาม `NF` แทนตำแหน่งตายตัว ⇒ **รองรับบรรทัดเก่าที่เขียนผิดรูปไปแล้วด้วย** (ไม่ต้องแก้ log ย้อนหลัง) และ objects ที่มีช่องว่างก็ไม่ขาด
