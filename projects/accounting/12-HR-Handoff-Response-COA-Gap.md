## 2. แก้ไขความเข้าใจผิดเรื่อง `event_code` — ไม่ใช่ shared optionset

จากเอกสาร handoff ของ HR สันนิษฐานว่า `event_code` เป็น shared optionset ที่ต้องแก้ผ่าน Browser เท่านั้น — **ข้อเท็จจริงคือ `event_code` เป็นฟิลด์ inline SingleSelect ธรรมดาบนตาราง `ac_posting_rule` เอง** (field id `6a85518c055f2288c5b7430b`) ไม่ผูกกับ optionset ที่ใช้ร่วมกับตารางอื่น จึงแก้ผ่าน MCP (`update_worksheet.editFields`) ได้ตรง ๆ โดยไม่ต้องพึ่ง Browser

เพิ่ม 2 option ใหม่สำเร็จแล้ว:

| ค่า (label) | key |
|---|---|
| PAYROLL_ACCRUAL | `ad4850c4-f1c1-4a65-adbb-fb0054a6e0c8` |
| PAYROLL_PAYMENT | `04a14b13-73c2-408b-a5fb-bb81ff630a06` |

ยืนยันหลังแก้ว่าฟิลด์มีครบ 12 option ไม่มีตัวซ้ำ, `name`("รหัสเหตุการณ์")/`alias`("event_code") ของฟิลด์ยังถูกต้องครบ (ระหว่างทางเจอบั๊กแพลตฟอร์มที่ `editFields` ล้าง `name`/`alias` เงียบถ้าไม่ส่งกลับไปด้วย — แก้ไขและบันทึกเป็นกับดักข้อ 32 ในเอกสาร memory ของฝั่งบัญชีแล้ว เผื่อฝั่ง HR เจอพฤติกรรมเดียวกันตอนแก้ field อื่นผ่าน `editFields`)

**สิ่งที่ HR ต้องทำต่อ**: ใช้ค่า `PAYROLL_ACCRUAL` (ตอนตั้งยอดค้างจ่ายเงินเดือน) และ `PAYROLL_PAYMENT` (ตอนจ่ายจริง) เป็น event ใน `ac_posting_rule` record ที่จะสร้างสำหรับ mapping บัญชีเงินเดือนต่อไป

## 3. Source of Truth สำหรับ WF-HR-10 — endorsed แล้ว

ฝ่ายบัญชี endorse การตัดสินใจของ HR สำหรับ WF-HR-10 ตามที่เสนอมา:

- **`ac_posting_rule` เป็นแหล่งข้อมูลหลัก (primary)** — ถ้ามี record ที่ match ทั้ง `event_code` และเงื่อนไขอื่นที่เกี่ยวข้อง ให้ใช้ mapping debit/credit จาก `ac_posting_rule` ก่อนเสมอ
- **`hr_pay_component.biz_coa_account` เป็น fallback** — ใช้เฉพาะกรณีไม่พบ `ac_posting_rule` ที่ match สำหรับ component/event นั้น ๆ

หมายเหตุเพิ่มเติมจากฝั่งบัญชี (ไม่บล็อก WF-HR-10 แต่ฝากไว้พิจารณาในอนาคต): ปัจจุบันตอน AC ปิดปี (WF-AC-11) การยกยอดกำไรสะสมยังใช้ logic hardcode ไม่ได้ดึงจาก `ac_posting_rule` ที่ event เป็น "ปิดงวด" (เนื่องจาก `source_module` ไม่มีตัวเลือก CLOSING จริงในตอนนั้น) — ถ้าฝั่ง HR หรือทีมกลางต้องการให้ posting ของ payroll เดินตาม pattern เดียวกันทั้งระบบในอนาคต จุดนี้เป็นตัวอย่างที่ยังไม่ data-driven เต็มที่ ควรพิจารณาร่วมกันตอนออกแบบรอบถัดไป

## 4. ยังรอ — ยังไม่ยืนยันตัวเลขจริง (ห้ามใช้ค่าใน memory ก่อนตรวจกับผู้ใช้จริง)

รายการต่อไปนี้เกี่ยวข้องกับ Gap G-05 ของ HR (อัตราภาษี/ประกันสังคม) แต่ **ฝ่ายบัญชียังไม่ได้รับการยืนยันตัวเลขจริงจากผู้ใช้/ทีมบัญชีจริง** — จึงยังไม่มีการเติมค่าใด ๆ ลงระบบ และขอให้ทุกฝ่ายงดใช้ค่าที่ไม่ได้มาจากการยืนยันจริงในการ build ต่อ:

- อัตราเงินสมทบประกันสังคม (ทั้งฝั่งลูกจ้าง/นายจ้าง) และเพดานฐานเงินเดือนที่ใช้คำนวณ
- อัตรา/ขั้นบันไดภาษีเงินได้บุคคลธรรมดา (PIT) ที่ใช้หัก ณ ที่จ่าย
- เลขทะเบียนนิติบุคคล และเลขทะเบียนนายจ้างประกันสังคมของบริษัท

เมื่อฝ่ายใดได้รับตัวเลขที่ยืนยันแล้วจากผู้ใช้จริง กรุณาแจ้งกลับเพื่ออัปเดตทั้งสองฝั่งพร้อมกัน (จะไม่มีการ "เดา" ตัวเลขเหล่านี้ใส่ระบบไปก่อนโดยเด็ดขาด)
