## 3. งานซ่อมหลังเปลี่ยนชื่อ — ผลสรุป

### 3.1 ✅ Rollup ของ "ใบสำคัญ" — ซ่อมแล้ว ทดสอบผ่าน

การแก้ฟิลด์ผ่าน API ทำให้ Rollup 2 ตัวเปลี่ยนจาก "ผลรวมของเดบิต/เครดิต" กลายเป็น **"จำนวนบันทึก"** และหยุดคำนวณใหม่
**ยืนยันตอนพัง:** แก้ยอดเดบิตในบรรทัดจาก 100 → 123.45 แล้วยอดรวมบนหัวเอกสารไม่ขยับเลย
**ผลกระทบที่หลีกได้:** `ผลต่างเดบิต–เครดิต` ที่ WF-AC-01 ใช้ตรวจดุล จะอ่านค่าเก่า → ใบที่ไม่ดุลอาจผ่านการตรวจได้

**ซ่อมผ่านหน้าจอแล้ว** (API ทำไม่ได้ — ชนิด Rollup ไม่มีใน enum ของ API และการพยายามส่ง `sourceField` กลับทำให้ชื่อฟิลด์หายเพิ่ม)

| ฟิลด์ | ตั้งใหม่เป็น | ผลทดสอบ |
|---|---|---|
| รวมเดบิต | รายการในใบสำคัญ → **เดบิต** · ผลรวม · ทศนิยม 2 | แก้บรรทัดเป็น 123.45 → หัวเอกสารขึ้น 123.45 ผลต่าง 33.45 ✅ |
| รวมเครดิต | รายการในใบสำคัญ → **เครดิต** · ผลรวม · ทศนิยม 2 | คืนค่าเป็น 100 → กลับเป็น 100.00 / ผลต่าง 10.00 ✅ |

> ⚠️ ข้อสังเกตที่ต้องจำ: เมื่อ Rollup คำนวณใหม่ **`_updatedAt` ของหัวเอกสารไม่ขยับ** — ห้ามใช้ `_updatedAt` ของใบสำคัญเป็นตัวจับการเปลี่ยนแปลงของยอดรวม

## 4. เรื่องที่ควรรู้

### 4.1 กับดักของ `update_worksheet` ที่ค้นพบ (สำคัญสำหรับงานต่อไปทุกครั้ง)

1. ส่ง `name` (ระดับตาราง) พร้อม `editFields` ในคอลเดียว → `name` ถูกเมินเงียบ ๆ ต้องแยกคอล
2. `editFields` **รีเซ็ตทุก attribute ที่ไม่ได้ส่งไป** — `required`, `isTitle`, `precision` และ `subType` ของ Relation/Date/DateTime/Attachment/Collaborator
3. ฟิลด์ Number **ห้ามส่ง `subType`** (จะรั่วลง `unit` เป็นขยะท้ายตัวเลข) · Relation ที่ subType=2 ก็ห้ามส่ง
4. Text หลายบรรทัด ต้องส่งผ่าน `config:{textMode:"multiLine"}` ไม่ใช่ `subType`
5. ฟิลด์ชนิด `OrgRole` **ห้ามส่ง `type`** (ไม่อยู่ใน enum ของ API)
6. `get_worksheet_structure` คืนชื่อตารางเป็นค่าเก่าเสมอ — ต้องตรวจด้วย `get_app_worksheets_list`
7. **Rollup — ห้ามใส่ลง `editFields` เด็ดขาด** จะเปลี่ยนเป็น "จำนวนบันทึก" และหยุดคำนวณ · ชนิด Rollup ไม่มีใน enum ของ API จึงซ่อมได้เฉพาะผ่านหน้าจอ
8. **Dropdown ที่ผูก optionset ส่วนกลาง — ห้ามใส่ลง `editFields`** การผูกจะหลุดถาวร และ**ผูกกลับเข้าฟิลด์เดิมไม่ได้ทั้ง API และหน้าจอ** ทางเดียวคือลบฟิลด์แล้วสร้างใหม่ (สำรองค่าในเรคคอร์ดก่อน)
9. ถ้าจะเปลี่ยนชื่อฟิลด์พวกนี้ ให้ทำผ่านหน้าจอเท่านั้น — หน้าจอไม่ทำให้อะไรหลุด

### 4.2 สิ่งที่พิสูจน์แล้วว่าไม่เสียหาย
- option key (GUID) ทุกตัวคงเดิม → เงื่อนไขใน workflow ที่เทียบ option key ยังทำงาน
- workflow อ้างฟิลด์ด้วย field ID → การเปลี่ยนชื่อและ alias ไม่กระทบ
- สูตร `ผลต่างเดบิต–เครดิต` ยังอยู่ (`$6a8603f4…$-$6a8604c0…$`) และกลับมาคำนวณถูกต้องแล้วหลังซ่อม §3.1
- ค่า `defaultValue = 0` ของฟิลด์ธง ยังส่งกลับไปทุกครั้งเพื่อกันหาย
