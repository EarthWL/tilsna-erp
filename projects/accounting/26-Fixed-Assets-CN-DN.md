## 4. 🔴🔴 ความผิดพลาดที่เกิดขึ้นจริงในงานนี้ — และวิธีที่จับได้

### 4.1 ใช้ ID ที่ "ต่อเติมเอง" จากบันทึกที่ถูกตัดท้าย

บันทึกสรุปเก่าเขียน ID ไว้แบบย่อ (`410101 bf7ba06c-…`) · agent เอาไปใช้โดย**เดาส่วนที่เหลือ** ได้ `bf7ba06c-4a71-4f66-9c9f-ff5e01d1ee27`
ของจริงคือ `bf7ba06c-6f39-43ee-a33b-768b04caf5d2` — **8 ตัวแรกตรงกัน ที่เหลือมั่วทั้งหมด**

ผล: บรรทัดรายได้ของใบสำคัญ CN/DN 5 บรรทัดชี้ไปบัญชีที่ไม่มีอยู่ ⇒ GL แสดง `Deleted` (อาการเดียวกับ D-44)
**ตัวเลข Dr/Cr ถูกหมด งบยังดุล** จึงไม่มีอะไรฟ้อง — เจอเพราะสคริปต์คำนวณงบ `KeyError` ตอน map บัญชีกลับผังบัญชี

แก้แล้วทั้ง 5 บรรทัดใน GL และ 5 บรรทัดในใบสำคัญ · ตรวจซ้ำทั้งระบบ: ไม่เหลือบัญชีเสียแม้แต่บรรทัดเดียว
🔑 **กฎใหม่: ID ที่เห็นแบบย่อ (มี `…`) ห้ามนำไปใช้ ต้องอ่านจากเซิร์ฟเวอร์ใหม่เสมอ** → **D-56**

### 4.2 เขียนทับยอดคงค้างของใบแจ้งหนี้ 5 ใบด้วยค่าที่อ่านไม่ได้

สคริปต์ปรับยอดใช้ `R.get_record(...) if hasattr(...)` — เงื่อนไขไม่เข้า ได้ `None` แล้ว fallback เป็น 0
⇒ เขียนยอดคงค้างใหม่เป็น "แค่ผลต่าง" ทับของเดิม · ยอดค้างรับรวมเพี้ยนจาก 2,018,890 เหลือ 649,050

**จับได้ทันทีเพราะสคริปต์พิมพ์บรรทัดตรวจ "ใบกำกับ vs ใบแจ้งหนี้ ตรงกันไหม" ไว้ท้ายทุกครั้ง** — ขึ้น 🔴 ในรอบเดียวกับที่เขียน
ซ่อมโดยยืนยันความสัมพันธ์บนใบที่ไม่ได้แตะก่อน (27/27 ใบ ยอดตรงกับใบกำกับ) แล้วคำนวณค่าที่ถูกกลับเข้าไป
🔑 **บทเรียน: `hasattr` guard ที่ fallback เป็นค่าว่างแล้วเอาไปเขียนทับ = ทำลายข้อมูลเงียบ ๆ · ถ้าอ่านค่าเดิมไม่ได้ ต้องหยุด ไม่ใช่ใช้ 0**

### 4.3 บัญชีปรับมูลค่า (contra) ทำให้งบดุลไม่ลง

ค่าเสื่อมราคาสะสม 1202xx เป็นบัญชีชนิด **Asset** แต่ดุลปกติเป็น **เครดิต**
สูตรเดิมคิดยอดตาม "ดุลปกติ" แล้วบวกเข้าสินทรัพย์ ⇒ สินทรัพย์เกินไป **2 เท่าของค่าเสื่อมสะสม** (ผลต่าง 219,933.30 = 2 × 109,966.65)

แก้โดยแยกสูตร: **งบทดลอง** ใช้ดุลปกติ (ถูกต้องตามรูปแบบงบทดลอง) · **งบแสดงฐานะการเงิน** เซ็นตามชนิดบัญชี (`Dr − Cr` สำหรับ Asset ทุกตัว) ⇒ contra ออกมาติดลบและไปหักยอดเอง

## 5. 🟡 เรื่องที่เจอ ไม่ได้เกิดจากงานนี้

**บัญชีคุมลูกหนี้ไม่ตรงกับบัญชีย่อย 1,200,000.00 บาท**
GL บัญชี 110201 = 3,218,890.00 · ผลรวมยอดค้างรับจากใบแจ้งหนี้ = 2,018,890.00
ผลต่างนี้มีมาก่อนงานนี้ (เดิม 3,214,630 vs 2,014,630 = 1,200,000 เท่ากัน) — มาจาก**ยอดลูกหนี้ยกมาต้นปีที่ไม่มีเอกสารย่อยรองรับ**
ไม่ใช่ข้อผิดพลาดของการบันทึก แต่เป็นช่องว่างของข้อมูลตั้งต้น ⇒ เปิดเป็น AC-R-29

## 6. ค้างอยู่

- **ใบตัดจำหน่ายสินทรัพย์ยังว่าง** — ตารางและฟิลด์พร้อมแล้ว แต่สินทรัพย์ทั้ง 8 รายการเพิ่งซื้อในปีนี้ การตัดจำหน่ายทันทีไม่สมจริง · และยังขาดฟิลด์ `gain_loss_account` บนประเภทสินทรัพย์ตามที่สเปก FR-05.7 ระบุไว้ ⇒ **ไม่ใส่ข้อมูลปลอม** รอตัดสินใจ
- **WF-AC-07 (คิดค่าเสื่อมอัตโนมัติรายเดือน) ยังไม่ได้สร้าง** — ชุดนี้คำนวณด้วยสคริปต์ · สเปกระบุ trigger เป็น `schedule` ซึ่งยิงทดสอบผ่าน MCP ไม่ได้ ต้องกด "Execute now" บนหน้าเว็บ
- **มูลค่าซาก = 0 ทุกรายการ** และ **คิดค่าเสื่อมเต็มเดือนในเดือนที่ได้มา** — สองข้อนี้ agent เลือกเอง ต้องให้นักบัญชียืนยัน (AC-R-30)
- **AC-08 เชื่อมต่อระบบและรับข้อมูล ยังว่างสนิท** — ไม่มีตารางเลย
