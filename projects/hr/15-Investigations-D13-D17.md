## D-13 · root cause จริง = ต้อง publish inner ก่อน outer

- 🟢🆕 **[แก้ไข 28 ส.ค. 2569 (ต่อเนื่อง 10) — D-13 ไม่ใช่บั๊กแพลตฟอร์ม เป็นขั้นตอนที่ขาดไปเอง — คลี่คลายแล้ว!] Root cause ที่แท้จริง: ต้อง `publish_process` ที่ inner processId ของ `sub_process` ก่อน แล้วจึง `validate_process`/`publish_process` ที่ outer/main process — ไม่ใช่แค่ `validate_process` ที่ inner (valid:true อย่างเดียวไม่พอ)** ทุกครั้งที่ผ่านมา (รวมการ reconfirm 28 ส.ค. เช้า) เรา validate inner แล้วเห็น `valid:true, canPublish:true` ก็เข้าใจว่า "โครงสร้างข้างในถูกต้องแล้ว" แล้วข้ามไป validate/publish outer ตรง ๆ โดยไม่เคยเรียก `publish_process` บน inner processId จริง ๆ เลยสักครั้ง — พบวิธีแก้จากเอกสารอ้างอิงของ skill **`hap-mcp-app-builder`** (คนละ skill กับ `nocoly-hybrid-builder-v2` ที่ session นี้ใช้หลัก) ไฟล์ `workflow_rules.md` ระบุชัดเจนว่า "含子流程/审批块时的发布顺序（违反必报 NodeAppIsNull 致命错误）... 正确流程：创建内部节点后 → 调 publish_process（内部 processId）立即发布该子流程 → 所有子流程发布成功后 → 调 publish_process（主流程 processId）最后发布主流程" — และ `nocoly-hybrid-builder-v2/references/workflow-authoring-mcp.md` บรรทัด 155 ก็มีกฎเดียวกันเขียนสั้น ๆ ไว้อยู่แล้ว ("Publish inner flows before the outer one, or the outer publish throws NodeAppIsNull") (`delete_process` แยกทั้ง outer และ inner เพราะลบ outer ไม่ cascade ลบ inner ให้อัตโนมัติ — inner จะกลายเป็น orphan process ค้างอยู่ถ้าไม่ลบเอง) ⇒ **กฎใหม่บังคับที่ต้องจำตลอดไป: ทุกครั้งที่มี - ~~🔴🔴 [เดิม, เข้าใจผิด] `sub_process` container node → `NodeAppIsNull` ตอน `validate_process`/`publish_process` (บั๊กแพลตฟอร์ม ยังไม่มีทางแก้จากฝั่ง MCP)~~ — สร้าง `sub_process` node (mode
