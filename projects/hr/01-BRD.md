## 1. บทนำ

### 1.1 วัตถุประสงค์เอกสาร
กำหนดความต้องการทางธุรกิจของโมดูลทรัพยากรบุคคล เพื่อให้ (ก) ผู้บริหารและผู้ตรวจรับใช้ตรวจสอบขอบเขตและเกณฑ์การยอมรับ และ (ข) เป็นต้นทางของ Build Spec ที่ build agent ใช้สร้างระบบจริงบน Nocoly

### 1.2 ขอบเขตระบบ (โดยย่อ)
ระบบบริหารทรัพยากรบุคคลแบบครบวงจรบนแอปเดียวกับโมดูลบัญชี ครอบคลุม **ทะเบียนพนักงานและโครงสร้างองค์กร · การลา · การลงเวลาและล่วงเวลา · เงินเดือนและภาษี/ประกันสังคม · สวัสดิการและการเบิกค่าใช้จ่ายพนักงาน · การสรรหา การประเมินผล และการฝึกอบรม** พร้อมเชื่อมรายการเงินเดือนและใบเบิกเข้าโมดูลบัญชีที่มีอยู่แล้ว

### 1.3 ระดับรายละเอียด
ระดับธุรกิจและ FR ระดับสูงเท่านั้น รายละเอียด implementation (worksheet / field / option key / workflow node / permission matrix) อยู่ใน Build Spec

### 1.4 กรอบกฎหมาย / ระเบียบ / นโยบายอ้างอิง
องค์กรเป็น **ภาคเอกชนที่ต้องรองรับรูปแบบเอกสารราชการ** ⇒ ต้องอ้างทั้งสองกรอบ

| ด้าน | อ้างอิง | ผลต่อระบบ |
|---|---|---|
| แรงงาน | พ.ร.บ.คุ้มครองแรงงาน พ.ศ. 2541 และที่แก้ไขเพิ่มเติม | สิทธิลาขั้นต่ำ (ลาป่วย 30 วัน/ปี · ลากิจธุระจำเป็น 3 วัน/ปี · ลาพักผ่อน 6 วัน/ปี หลังทำงานครบ 1 ปี · ลาคลอด 98 วัน) · อัตราค่าล่วงเวลา 1.5 / 1.0 / 3.0 เท่า · ชั่วโมงทำงานไม่เกิน 8 ชม./วัน 48 ชม./สัปดาห์ |
| ประกันสังคม | พ.ร.บ.ประกันสังคม พ.ศ. 2533 | หักเงินสมทบลูกจ้าง 5% ของค่าจ้าง โดยมีเพดานฐานค่าจ้างตามประกาศที่บังคับใช้ · นายจ้างสมทบเท่ากัน · นำส่ง สปส.1-10 รายเดือน |

| ข้อมูลส่วนบุคคล | พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) | ข้อมูลอ่อนไหว (เลขบัตรประชาชน · ประวัติสุขภาพ · เอกสารการลาป่วย · บัญชีธนาคาร · เงินเดือน) ต้องจำกัดสิทธิ์เข้าถึงและมี audit trail |
| เอกสารรูปแบบราชการ | ระเบียบสำนักนายกรัฐมนตรีว่าด้วยงานสารบรรณ (เฉพาะรูปแบบเอกสาร) | ใบลา · หนังสือรับรองเงินเดือน · หนังสือรับรองการทำงาน ต้องพิมพ์ในรูปแบบเอกสารราชการ (ฟอนต์ TH Sarabun New · เลขไทย) |
| นโยบายภายใน | การแบ่งแยกหน้าที่ (Segregation of Duties) | ผู้บันทึกข้อมูลพนักงาน ≠ ผู้คำนวณเงินเดือน ≠ ผู้อนุมัติจ่าย · ผู้ดูแลระบบห้ามมีสิทธิ์อนุมัติ |

> ⚠️ ตัวเลขอัตราและเพดานทั้งหมด (เพดานฐานประกันสังคม · ขั้นบันไดภาษี · ค่าลดหย่อน) **ต้องเก็บเป็นข้อมูลในตารางตั้งค่าแบบมีวันที่มีผล ห้าม hard-code ใน workflow** เพราะเปลี่ยนตามประกาศราชการ (ดู BR-14)

## 3. วัตถุประสงค์ทางธุรกิจ (Business Objectives)

## 4. ขอบเขต

### In scope
1. ทะเบียนพนักงาน ตำแหน่ง ระดับ สัญญาจ้าง และโครงสร้างการบังคับบัญชา
2. ผู้ติดตาม/ผู้ใช้สิทธิลดหย่อน และบัญชีธนาคารพนักงาน
3. ประเภทการลา · นโยบายสิทธิลา · ใบลา · ยอดสิทธิคงเหลือ · รายการเคลื่อนไหวสิทธิ · การยกยอดต้นปี
4. ปฏิทินวันหยุด · กะการทำงาน · บันทึกลงเวลารายวัน · การสรุปสาย/ขาด/ชั่วโมงทำงาน
5. ใบขออนุมัติล่วงเวลา และการคิดอัตรา OT ตามกฎหมาย
6. งวดจ่ายเงินเดือน · โครงสร้างเงินเดือนรายบุคคล · องค์ประกอบรายได้–รายหัก · สลิปเงินเดือน
7. เงินสมทบประกันสังคม · ภาษีเงินได้หัก ณ ที่จ่าย · การยื่น ภ.ง.ด.1 / 1ก · หนังสือรับรองการหักภาษี
8. สวัสดิการและวงเงินต่อคน/ปี · ใบเบิกสวัสดิการและค่าใช้จ่ายพนักงาน
9. ใบขออัตรากำลัง · ผู้สมัคร · การสัมภาษณ์ · การจ้าง
10. รอบประเมิน · แบบประเมินผล · KPI/สมรรถนะ
11. หลักสูตรและการเข้าอบรม พร้อมผลการอบรม
12. การเชื่อมต่อกับโมดูลบัญชีเดิม: สร้างใบสำคัญเงินเดือน และส่งใบเบิกเข้าใบขออนุมัติเบิกจ่าย
13. บทบาทและสิทธิ์ 8 บทบาท พร้อมการปิดบังข้อมูลอ่อนไหว
14. รายงานและแดชบอร์ดหลักของ HR

### Out of scope (เฟสนี้)
- การเชื่อมต่อกับเครื่องสแกนลายนิ้วมือ/ใบหน้าแบบอัตโนมัติ (เฟสนี้นำเข้าไฟล์หรือบันทึกด้วยมือ)
- การยื่นแบบภาษีและประกันสังคมผ่านช่องทางอิเล็กทรอนิกส์ของหน่วยงานโดยตรง (ระบบออกไฟล์/รายงานให้ แต่คนเป็นผู้ยื่น)
- การจ่ายเงินเดือนผ่าน API ธนาคารโดยตรง (ระบบออกไฟล์นำส่งธนาคาร)
- แอปมือถือเฉพาะทาง (ใช้เว็บ/แอป Nocoly มาตรฐาน)
- การบริหารกองทุนสำรองเลี้ยงชีพเชิงลึก (บันทึกยอดหักได้ แต่ไม่บริหารพอร์ต)
- ระบบ e-Signature ภายนอก

## 6. กระบวนการเป้าหมาย (To-Be)

**6.1 การลา**
พนักงานสร้างใบลา → ระบบตรวจสิทธิคงเหลือและวันซ้อนทับตอนกรอก → กดปุ่ม "ส่งคำขอ" → หัวหน้างานอนุมัติ → HR ตรวจสิทธิและอนุมัติ → ระบบตัดสิทธิลา บันทึกรายการเคลื่อนไหว และเชื่อมกับบันทึกลงเวลาของวันนั้น → แจ้งผลกลับพนักงาน
กรณีลาเกิน N วัน เพิ่มขั้นผู้บริหารก่อน HR · กรณียกเลิกใบลาที่อนุมัติแล้ว ระบบคืนสิทธิให้อัตโนมัติ

**6.2 การลงเวลาและล่วงเวลา**
บันทึกเวลาเข้า-ออกรายวัน (นำเข้าไฟล์หรือบันทึกเอง) → ระบบสรุปรายวันเทียบกะและวันหยุด แล้วระบุสถานะ (ปกติ/สาย/ขาด/ลา/วันหยุด) → OT ต้องมีใบขออนุมัติล่วงหน้าและอนุมัติ 2 ระดับก่อนจึงนำไปคิดค่าจ้าง

**6.3 เงินเดือน**
เปิดงวดจ่าย → สร้างสลิปให้พนักงานที่ยัง active ทั้งหมด → ระบบดึงรายได้ประจำจากโครงสร้างเงินเดือน + OT ที่อนุมัติ + หักลาไม่รับค่าจ้าง/ขาดงาน → คำนวณประกันสังคมและภาษีหัก ณ ที่จ่าย → HR Manager อนุมัติงวด → ระบบสร้างใบสำคัญเงินเดือนในโมดูลบัญชี → ปิดงวดและเผยแพร่สลิปให้พนักงาน → จัดทำ ภ.ง.ด.1 และรายงานประกันสังคม

**6.4 สวัสดิการและการเบิกค่าใช้จ่าย**
พนักงานสร้างใบเบิกและแนบหลักฐาน → ระบบแสดงวงเงินคงเหลือและบล็อกการบันทึกเมื่อเกินสิทธิ → หัวหน้างานอนุมัติ → HR ตรวจและอนุมัติ → ระบบตัดวงเงินและส่งเรื่องเข้าใบขออนุมัติเบิกจ่ายของโมดูลบัญชีเพื่อจ่ายจริง

**6.5 สรรหา ประเมิน อบรม**
ใบขออัตรากำลัง → อนุมัติ → รับผู้สมัครและเลื่อนสถานะตามขั้น → สัมภาษณ์และบันทึกผล → จ้างแล้วสร้างทะเบียนพนักงานจากข้อมูลผู้สมัคร
รอบประเมินเปิด → ระบบสร้างแบบประเมินให้ทุกคน → พนักงานประเมินตนเอง → หัวหน้าประเมิน → HR สรุปและปิดรอบ
แผนอบรม → ลงทะเบียน → บันทึกผลและใบรับรอง → ผูกกลับประวัติพนักงาน

## 7. ความต้องการเชิงธุรกิจ (Business Requirements)

| รหัส | ความต้องการ | ความสำคัญ |
|---|---|---|
| BR-01 | พนักงานทุกคนต้องมีทะเบียนเดียวที่เป็นแหล่งความจริง และผูกกับบัญชีผู้ใช้ในระบบ | สูง |
| BR-02 | ทุกคำขอของพนักงานต้องผ่านการอนุมัติ 2 ระดับ (หัวหน้างาน → HR) และบันทึกผู้อนุมัติ เวลา และเหตุผลกรณีไม่อนุมัติ | สูง |
| BR-03 | ผู้อนุมัติขั้นที่ 1 ต้องมาจากฟิลด์ "ผู้บังคับบัญชา" บนทะเบียนพนักงาน ไม่ใช่การเลือกเอง | สูง |
| BR-04 | สิทธิการลาต้องคำนวณจากนโยบายที่ตั้งไว้ + อายุงาน และตัด/คืนอัตโนมัติเมื่ออนุมัติ/ยกเลิก | สูง |
| BR-05 | ห้ามบันทึกใบลาที่เกินสิทธิคงเหลือ หรือมีวันซ้อนทับกับใบลาที่อนุมัติแล้ว | สูง |
| BR-06 | ค่าล่วงเวลาต้องคิดจากใบขอ OT ที่อนุมัติแล้วเท่านั้น และใช้อัตราตามประเภทวัน (วันทำงาน/วันหยุด) | สูง |
| BR-07 | เงินเดือนต้องคำนวณจากโครงสร้างเงินเดือนที่มีวันที่มีผล ไม่ใช่ค่าที่พิมพ์ในสลิปโดยตรง | สูง |
| BR-08 | เงินสมทบประกันสังคมและภาษีหัก ณ ที่จ่าย ต้องคำนวณจากตารางอัตราที่มีวันที่มีผล | สูง |
| BR-09 | เมื่องวดจ่ายได้รับอนุมัติ ระบบต้องสร้างใบสำคัญเงินเดือนในโมดูลบัญชีโดยอ้างกฎการบันทึกบัญชี ไม่ hard-code รหัสบัญชี | สูง |
| BR-10 | ใบเบิกสวัสดิการที่อนุมัติแล้วต้องเข้าสู่กระบวนการเบิกจ่ายของโมดูลบัญชีโดยไม่ต้องพิมพ์ซ้ำ | สูง |
| BR-11 | ต้องกันวงเงินสวัสดิการไม่ให้เบิกเกินสิทธิต่อคนต่อปี | สูง |
| BR-12 | ข้อมูลอ่อนไหว (เงินเดือน · เลขบัตรประชาชน · เอกสารการลาป่วย · บัญชีธนาคาร) ต้องเห็นได้เฉพาะบทบาทที่ได้รับอนุญาต | สูง |
| BR-13 | ต้องแบ่งแยกหน้าที่: ผู้บันทึกทะเบียน ≠ ผู้คำนวณเงินเดือน ≠ ผู้อนุมัติ · ผู้ดูแลระบบไม่มีสิทธิ์อนุมัติ | สูง |
| BR-14 | อัตราและเพดานทุกชนิดต้องเก็บเป็นข้อมูลที่แก้ไขได้พร้อมวันที่มีผล ห้ามฝังใน workflow | สูง |
| BR-15 | สลิปเงินเดือนที่ปิดงวดแล้วต้องแก้ไขไม่ได้ ต้องแก้ด้วยการปรับปรุงในงวดถัดไปหรือกลับรายการ | สูง |
| BR-16 | พนักงานต้องเห็นสลิป สิทธิลาคงเหลือ และสถานะคำขอของตนเองได้ตลอดเวลา | กลาง |
| BR-17 | ต้องแจ้งเตือนเมื่อคำขอค้างอนุมัติเกิน SLA และเมื่อสัญญาจ้าง/ทดลองงานใกล้ครบกำหนด | กลาง |
| BR-18 | ใบลา หนังสือรับรองเงินเดือน และหนังสือรับรองการทำงาน ต้องพิมพ์ในรูปแบบเอกสารราชการได้ | กลาง |
| BR-19 | ผู้สมัครที่ถูกจ้างต้องสร้างทะเบียนพนักงานจากข้อมูลเดิมโดยไม่ต้องกรอกซ้ำ | กลาง |
| BR-20 | ผลประเมินและประวัติอบรมต้องผูกกับทะเบียนพนักงานและดูย้อนหลังได้ | กลาง |
| BR-21 | ต้องเก็บร่องรอยว่าใครแก้อะไรเมื่อไร โดยเฉพาะโครงสร้างเงินเดือนและสิทธิลา | สูง |
| BR-22 | ต้องยกยอดสิทธิลาต้นปีตามนโยบาย (ยกได้/ยกไม่ได้/ยกได้ไม่เกิน N วัน) โดยอัตโนมัติ | กลาง |

## 8. ความต้องการเชิงหน้าที่ระดับสูง (Functional Requirements)

| รหัส | โมดูล | คำอธิบายระดับสูง |
|---|---|---|
| FR-HR-01 | ตั้งค่าโมดูลบุคคล | เก็บค่าตั้งต้นระดับองค์กร: ชั่วโมงทำงานมาตรฐานต่อวัน วันเริ่มสัปดาห์ เวลาผ่อนผันการมาสาย รอบปีสิทธิลา (ปีปฏิทินหรือปีที่เริ่มงาน) วันตัดรอบเวลาสำหรับเงินเดือน และนโยบายการยกยอดสิทธิลา ค่าทั้งหมดแก้ไขได้โดยไม่ต้องแก้ workflow |
| FR-HR-02 | ปฏิทินวันหยุดและกะทำงาน | จัดเก็บวันหยุดประจำปี (วันหยุดราชการ/ประเพณี/บริษัท) และนิยามกะทำงาน (เวลาเข้า-ออก เวลาพัก ชั่วโมงมาตรฐาน) เพื่อให้การสรุปเวลาและการคิด OT อ้างอิงได้ |
| FR-HR-03 | ทะเบียนพนักงาน | ข้อมูลประจำตัว ข้อมูลติดต่อ วันเริ่มงาน สถานะการจ้าง ประเภทการจ้าง หน่วยงาน ตำแหน่ง ระดับ **ผู้บังคับบัญชา** และบัญชีผู้ใช้ในระบบ พร้อมข้อมูลอ่อนไหวที่จำกัดสิทธิ์เข้าถึง |
| FR-HR-04 | ตำแหน่งและระดับพนักงาน | ตารางอ้างอิงตำแหน่งงานและระดับ ใช้กำหนดสิทธิลา วงเงินสวัสดิการ และโครงสร้างเงินเดือน |
| FR-HR-05 | สัญญาจ้างและการเปลี่ยนสถานะ | บันทึกสัญญาจ้างแต่ละฉบับ (ทดลองงาน/ประจำ/ชั่วคราว) วันเริ่ม-สิ้นสุด และเหตุการณ์เปลี่ยนสถานะ (บรรจุ เลื่อนตำแหน่ง โอนย้าย ลาออก เลิกจ้าง) พร้อมแจ้งเตือนก่อนครบกำหนด |
| FR-HR-06 | ผู้ติดตามและบัญชีธนาคาร | ข้อมูลคู่สมรส/บุตร/บิดามารดา สำหรับการลดหย่อนภาษีและสวัสดิการ และบัญชีธนาคารสำหรับโอนเงินเดือน — ทั้งคู่เป็นข้อมูลอ่อนไหว |
| FR-HR-07 | ประเภทการลาและนโยบายสิทธิ | นิยามประเภทการลา (รับค่าจ้าง/ไม่รับ · ต้องแนบเอกสารหรือไม่ · ลาล่วงหน้ากี่วัน · ลาครึ่งวันได้หรือไม่) และนโยบายสิทธิต่อระดับ/อายุงาน พร้อมกฎการยกยอด |
| FR-HR-08 | ใบลา | สร้าง ส่งอนุมัติ ยกเลิก ติดตามสถานะ · คำนวณจำนวนวันลาโดยหักวันหยุดและวันหยุดประจำสัปดาห์ · บล็อกการบันทึกเมื่อเกินสิทธิหรือซ้อนทับ · แนบเอกสารประกอบ · พิมพ์แบบฟอร์มใบลา |
| FR-HR-09 | สิทธิและยอดคงเหลือการลา | เก็บยอดสิทธิ ยอดใช้ไป ยอดคงเหลือ ต่อพนักงาน × ประเภทการลา × ปีสิทธิ พร้อมรายการเคลื่อนไหวทุกครั้งที่เพิ่ม/หัก/ยกยอด เพื่อสอบทานย้อนหลังได้ |
| FR-HR-10 | บันทึกลงเวลารายวัน | บันทึกเวลาเข้า-ออกต่อคนต่อวัน (นำเข้าไฟล์หรือบันทึกเอง) แล้วสรุปสถานะรายวันเทียบกะ วันหยุด และใบลาที่อนุมัติ พร้อมชั่วโมงทำงานจริงและนาทีที่สาย |
| FR-HR-11 | ใบขออนุมัติล่วงเวลา | ขอ OT ล่วงหน้าพร้อมเหตุผลและช่วงเวลา · อนุมัติ 2 ระดับ · คิดอัตราตามประเภทวัน · เฉพาะที่อนุมัติแล้วจึงนำไปคิดค่าจ้าง |
| FR-HR-12 | งวดจ่ายเงินเดือนและองค์ประกอบค่าจ้าง | นิยามงวดจ่าย (เดือน/ครึ่งเดือน) พร้อมสถานะงวด และตารางองค์ประกอบรายได้–รายหักที่กำหนดวิธีคำนวณและผังบัญชีที่ผูก |
| FR-HR-13 | โครงสร้างเงินเดือนรายบุคคล | เก็บเงินเดือนและเงินประจำตำแหน่งต่อพนักงานแบบมีวันที่มีผล เพื่อให้ย้อนดูได้ว่าในงวดใดใช้อัตราใด |
| FR-HR-14 | สลิปเงินเดือน | สร้างสลิปทั้งงวดในครั้งเดียว · คำนวณรายได้ รายหัก ยอดสุทธิ · แสดงที่มาของทุกบรรทัด · ล็อกเมื่อปิดงวด · เผยแพร่ให้พนักงานดูเฉพาะของตนเอง |
| FR-HR-15 | ประกันสังคมและภาษีหัก ณ ที่จ่าย | คำนวณเงินสมทบตามอัตราและเพดานที่บังคับใช้ · คำนวณภาษีหัก ณ ที่จ่ายรายเดือนแบบประมาณการทั้งปีตามขั้นบันไดและค่าลดหย่อน · ออกรายงานนำส่ง |
| FR-HR-16 | การยื่น ภ.ง.ด.1 / 1ก และหนังสือรับรองหักภาษี | รวบรวมยอดหักภาษีของงวด/ปี จัดทำแบบยื่นและหนังสือรับรองการหักภาษี ณ ที่จ่าย (50 ทวิ) รายบุคคล |
| FR-HR-17 | เชื่อมเงินเดือนเข้าโมดูลบัญชี | เมื่องวดจ่ายได้รับอนุมัติ สร้างใบสำคัญและรายการในใบสำคัญของโมดูลบัญชีตามกฎการบันทึกบัญชี พร้อมระบุระบบต้นทางเป็น Payroll และป้องกันการสร้างซ้ำ |
| FR-HR-18 | สวัสดิการและวงเงิน | นิยามสวัสดิการ (ค่ารักษาพยาบาล ค่าเดินทาง ค่าเล่าเรียนบุตร ฯลฯ) วงเงินต่อระดับต่อปี และยอดคงเหลือรายบุคคล |
| FR-HR-19 | ใบเบิกสวัสดิการและค่าใช้จ่ายพนักงาน | สร้างใบเบิกพร้อมรายการและหลักฐาน · แสดงวงเงินคงเหลือขณะกรอก · บล็อกเมื่อเกินสิทธิ · อนุมัติ 2 ระดับ · ตัดวงเงิน · ส่งเข้ากระบวนการเบิกจ่ายของบัญชี |
| FR-HR-20 | ใบขออัตรากำลังและการสรรหา | ขออัตรากำลังพร้อมเหตุผลและงบประมาณ · อนุมัติ · เปิดรับสมัคร · บันทึกผู้สมัครและเลื่อนสถานะตามขั้นตอน |

| A-HR-17 | ผู้บังคับบัญชาเก็บเป็นฟิลด์บนทะเบียนพนักงาน ไม่ใช้โครงสร้างหน่วยงานของแพลตฟอร์ม | ฟิลด์บนทะเบียน |
| A-HR-18 | ข้อมูลผู้สมัครที่ไม่ได้รับการว่าจ้างเก็บไว้ 1 ปีแล้วลบ | 1 ปี |

### ข้อจำกัดที่ยืนยันแล้ว (ไม่ใช่ข้อสมมติ)
1. **ทุก business logic ต้องอยู่บน Nocoly เท่านั้น** — ห้ามใช้สคริปต์หรือไฟล์ภายนอกเป็นส่วนหนึ่งของระบบที่ส่งมอบ
2. **โมดูลนี้อยู่ในแอปเดิม** ที่มีโมดูลบัญชี 34 ตารางทำงานอยู่แล้ว — ห้ามสร้างของซ้ำหรือแก้ของเดิมโดยไม่จำเป็น
3. **การอนุมัติทำผ่าน API ไม่ได้** — ต้องมีคนกดจริงในรายการงาน ⇒ ห้ามปิดงานว่าทดสอบครบถ้วนถ้าขั้นอนุมัติยังค้าง
4. ชื่อตารางและชื่อฟิลด์ในแอปนี้เป็นภาษาไทยทั้งหมด — โมดูล HR ต้องทำตามแบบเดียวกัน
