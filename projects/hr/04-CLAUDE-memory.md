## ⚠️ ข้อกำหนดหลัก (CRITICAL CONSTRAINTS)

1. **ทุก business logic ต้องอยู่บน Nocoly เท่านั้น** — ห้ามใช้สคริปต์หรือไฟล์ภายนอกเป็นส่วนหนึ่งของระบบที่ส่งมอบ
2. **Greenfield ในแอป Brownfield** — HR ยังไม่มี object แม้แต่ชิ้นเดียว แต่แอปมี **โมดูลบัญชี 34 worksheet · 35 optionset · 8 custom role** ทำงานอยู่ 🔴 **ห้ามสร้างซ้ำ ห้ามแก้โครงสร้างของบัญชี** เปิด BuildSpec §1.4 ก่อนแตะอะไรที่ขึ้นต้น `ac_`
3. **การอนุมัติทำผ่าน MCP ไม่ได้** — ผู้อนุมัติต้องกดใน To-do จริง ⇒ **ห้ามปิดงาน ✅ ถ้า approval ยัง pending**
4. **ห้ามใช้ org-auth API กดอนุมัติแทนคน** (A-HR-15 — ผู้ใช้ยังไม่อนุญาต เช่นเดียวกับโมดูลบัญชี)
5. **ชื่อ worksheet และชื่อฟิลด์ต้องเป็นภาษาไทย** ให้เข้าชุดกับโมดูลบัญชี · alias เป็นอังกฤษ snake_case ขึ้นต้น `hr_`
6. **ข้อมูล HR เป็นข้อมูลส่วนบุคคล (PDPA)** — เงินเดือน · เลขบัตรประชาชน · เอกสารการลาป่วย · บัญชีธนาคาร ต้องปิดบังตาม §1.7 · เอกสารที่อนุมัติแล้ว **ห้ามลบ** ใช้ยกเลิก/กลับรายการแทน
7. **SoD บังคับ** — R5 Payroll และ R8 Admin **ห้ามมีสิทธิ์อนุมัติเด็ดขาด** · R5 แก้ทะเบียนพนักงานไม่ได้
